# 部署與設定

## 環境變數（後端參數）

Nuxt 用 `runtimeConfig` 讀設定（定義在 `nuxt.config.ts`），值由 `NUXT_` 開頭的環境變數覆蓋。
本機放在 `.env`（從 `.env.example` 複製，已被 git 忽略）；正式環境設在 Vercel 專案的 Environment Variables。

| 環境變數 | 必填 | 前端看得到 | 用途 | 取得方式 |
|---|:-:|:-:|---|---|
| `NUXT_SUPABASE_URL` | ✅ | ❌ | Supabase 專案網址 | Supabase 後台 → Project Settings → API |
| `NUXT_SUPABASE_SERVICE_ROLE_KEY` | ✅ | ❌ | 後端存取資料庫的金鑰，**繞過所有資料表權限**，絕不可公開或提交 | Supabase 後台 → Project Settings → API Keys → `service_role`（或 secret key） |
| `NUXT_SESSION_SECRET` | ✅ | ❌ | 簽登入憑證，至少 32 字元；**換掉會讓所有人需要重新登入** | 自己產生：`node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"` |
| `NUXT_LINE_CHANNEL_ID` | ✅ | ❌ | 驗證 LINE idToken 是發給本站的（比對 `aud`） | LINE Developers → LINE Login channel → Basic settings → Channel ID（與正式版同一個 channel） |
| `NUXT_PUBLIC_LIFF_ID` | ✅ | ✅ | 前端初始化 LIFF | LINE Developers → 同一個 channel → LIFF 分頁 → Nuxt 版的 LIFF app |
| `NUXT_DEV_LOGIN` | 本機 | ❌ | `1`＝開後端測試登入 API（正式建置一律關閉） | 本機設 `1`，**Vercel 不要設** |
| `NUXT_PUBLIC_DEV_LOGIN` | 本機 | ✅ | `1`＝前端顯示測試登入畫面（正式建置一律關閉） | 本機設 `1`，**Vercel 不要設** |

> 開關類變數用 `isFlagOn()` 判斷：Nuxt 會把 `1` 讀成數字，`1`／`true` 都算開。
> 前端看得到的（`NUXT_PUBLIC_`）會被打包進瀏覽器，只能放可公開的值；金鑰一律不加 `PUBLIC`。

## 本機開發

```bash
pnpm install
cp .env.example .env     # 填入 NUXT_SUPABASE_SERVICE_ROLE_KEY 等（見上表）
pnpm dev                 # http://localhost:3000（加 --port 3001 換 port）
```

- 本機無法用 LINE 登入（LIFF 只接受 https），`.env` 設 `NUXT_DEV_LOGIN=1`、`NUXT_PUBLIC_DEV_LOGIN=1` 後開首頁會出現「開發用測試登入」，可選一般成員／二級／一級管理員（見 [登入系統](登入系統.md)）。
- 改了 `.env` 要重啟 `pnpm dev` 才會生效。
- 不用登入的頁面：`/privacy`（隱私權政策）、`/ui-preview`（元件預覽，示範資料）。

## 指令

| 指令 | 做什麼 |
|---|---|
| `pnpm dev` | 開發伺服器（改程式自動更新畫面） |
| `pnpm test` | 單元與元件測試（Vitest＋happy-dom，不需要資料庫） |
| `pnpm typecheck` | 型別檢查（vue-tsc） |
| `pnpm build` | 正式建置，產物在 `.output/` |
| `node .output/server/index.mjs` | 在本機執行正式建置版（`PORT=3099` 可換 port） |

上線前至少跑：`pnpm test`、`pnpm typecheck`、`pnpm build` 三個都要過。

### 建置相關設定
- **套件管理用 pnpm**。pnpm 10 預設擋套件的安裝腳本，`package.json` 的 `pnpm.onlyBuiltDependencies` 已允許 `esbuild`（Nuxt 打包需要）。
- **TypeScript 刻意用 5.x**：vue-tsc 尚未支援 TypeScript 7。
- **只在瀏覽器端渲染**（`ssr: false`）：正式建置後頁面是靜態檔，API 由 Nitro 伺服器提供。

## Supabase（資料庫）

Nuxt 版用**獨立的新專案**（`eetmnranpbdkolzgbimj`），跟正式運作中的 Next.js 版資料庫分開，開發中的程式不會動到真實成員資料。

### 建立資料表
`supabase/migrations/` **依檔名順序全部套用**：001～045 與 Next.js 版逐字一致，046 是 Nuxt 版專用（見下方）。
- Claude 端：Supabase 連線（MCP）切到新專案的帳號後，用 `apply_migration` 逐一套用。
- 或自己用 Supabase CLI：`supabase db push`（需要資料庫密碼）。

**目前狀態（2026-10-02）**：001～046 已全部套用到 `eetmnranpbdkolzgbimj`，套用後檢查結果：

| 項目 | 結果 |
|---|---|
| 資料表 | 14 張，全部開啟 RLS（資料列權限控管） |
| 排程（pg_cron） | 5 個：`generate_sessions`（每日補場次）、`build_summary_month`、`build_summary_quarter`、`purge_details`、`purge_inactive_users`；時間皆為 UTC |
| Storage | `archives`（私有，放封存報表） |
| 全站設定 | 往後生成 12 週、單場退費 234 元 |
| 安全檢查（security advisor） | 無警告 |
| 效能檢查 | 只剩「索引尚未使用」（資料庫還是空的）與「同表多條讀取規則」（沿用正式版；前端不直接連資料庫，不影響） |

**046 為什麼只有 Nuxt 版有**：建新專案時勾了「新資料表自動開 RLS」，Supabase 會自動建一支 `rls_auto_enable()` 函式，安全檢查會對它發警告。046 收回前端角色的執行權限；它是資料庫自己觸發的，收回後自動開 RLS 照常運作。

套用後還要做：
1. Database → Extensions 確認 `pg_cron` 已啟用（migration 003／013 會嘗試啟用）。
2. 用測試登入或 LINE 登入一次，再到 SQL Editor 指定第一位一級管理員：
   ```sql
   update users set role = 'admin1' where display_name = '你的 LINE 名稱';
   ```

### 金鑰與密碼
- 程式只需要 service role 金鑰（上表），**不需要資料庫密碼**。
- 資料庫密碼若曾外流（例如貼在對話或訊息裡），到 Settings → Database → Reset database password 換掉，對程式沒有影響。

## LINE LIFF

Nuxt 版在**同一個 LINE Login channel** 底下另建一個 LIFF app（正式版的 LIFF app 不動）：

1. [LINE Developers](https://developers.line.biz/) → 正式版用的 LINE Login channel → **LIFF** 分頁 → Add。
2. 設定：
   - **Size**：Full
   - **Endpoint URL**：`https://leave-system1-fawn.vercel.app/`（Nuxt 版在 Vercel 的正式網址）
   - **Scopes**：勾 `openid`、`profile`
3. 建好後複製 **LIFF ID**，設到 `NUXT_PUBLIC_LIFF_ID`（Vercel 與本機 `.env`）。
4. 同一個 channel 的 **LINE Login** 分頁 → **Callback URL** 加上 Nuxt 版網址（外部瀏覽器登入完導回首頁要用）。

## Vercel（網站代管）

正式網址：**https://leave-system1-fawn.vercel.app**（已匯入 repo，推到 `main` 會自動部署）

1. Vercel → Add New → Project → Import Git Repository → 選 `boan-chen047/leave-system1`。
2. Framework 會自動偵測為 Nuxt，建置指令 `pnpm build`、輸出由 Nuxt 處理，不用改。
3. Environment Variables：加入上表「必填」的 5 個（`NUXT_DEV_LOGIN`、`NUXT_PUBLIC_DEV_LOGIN` **不要加**）。
   - `NUXT_SESSION_SECRET` 正式環境請另外產生一組，不要和本機 `.env` 共用。
4. Deploy。之後推到 `main` 就會自動部署。
5. 拿到正式網址後，回 LINE 設定 LIFF Endpoint URL 與 Callback URL（上一節）。

> **改了環境變數要重新部署才會生效**：Vercel → Deployments → 最新一筆 → Redeploy。

部署後檢查：
- 開 `https://<網址>/privacy` 應正常顯示（不需登入）。
- `GET https://<網址>/api/me` 應回 **401** 的 JSON `{"error":"未登入"}`。若回的是網頁 HTML，代表部署的版本還沒有後端 API（第 1 步時的 `main` 就是這樣）。
- `POST https://<網址>/api/auth/dev-login` 應回 **404**（測試登入在正式環境不存在）。
- 從 LINE 開 LIFF 網址 `https://liff.line.me/<LIFF ID>`，應進入首次設定或首頁。
