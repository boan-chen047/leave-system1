# 架構與模組

## 整體結構

Nuxt 版把畫面和後端 API 放在同一個專案。瀏覽器只負責畫面，**所有資料都經過本站後端存取資料庫**，前端從不直接連 Supabase。

```
瀏覽器（Vue 畫面，ssr: false）
   │  fetch /api/...（自動帶登入 cookie）
   ▼
本站後端（server/，Nitro）── 用 service role 金鑰 ──▶ Supabase（PostgreSQL）
   │
   └── 驗證 LINE 登入 ──▶ LINE 平台
```

- **只在瀏覽器端渲染（`ssr: false`）**：LINE LIFF 只能在瀏覽器執行、每頁資料都要登入後才有、不需要搜尋引擎收錄。後端 API 不受影響，照常在伺服器執行。
- **為什麼前端不直接連資料庫**：資料表的權限控管（誰能看誰的資料、管理員分級）全部寫在後端 API，前端拿不到任何資料庫金鑰。

## 目錄

```
app/                  前端（Vue）
  app.vue             根元件：外框 → AuthGate（登入閘門）→ 版面 → 頁面
  layouts/default.vue 成員頁共用版面：整頁一個螢幕高、內容區自己捲、底部分頁列
  pages/              頁面（檔名＝網址，例：pages/cancel.vue → /cancel）
  components/         元件（自動匯入，不用 import）
    ui/               基礎元件，用時加 Ui 前綴：<UiButton> <UiDialog> <UiInput> …
    dialogs/          對話框，不加前綴：<NameDialog> <ConfirmDialog> …
  composables/        共用狀態與流程（useMe：目前登入者＋登入流程）
  utils/              前端工具函式（api 呼叫、cache 短暫快取、liff）
  assets/css/main.css 配色與全站樣式
server/               後端（Nitro）
  api/                API（檔名＝網址＋方法，例：api/me/terms.patch.ts → PATCH /api/me/terms）
  utils/              後端工具（自動匯入）：資料庫連線、登入憑證、權限判斷、LINE 驗證、
                      在隊判斷（membership）、個人統計（memberStats）、id 格式檢查（uuid）
shared/               前後端共用（兩邊都自動匯入）
  types/              資料型別（Me、SessionRow …）
  utils/              共用規則：日期與請假截止、條款版本、首次設定判斷、銀行代號檢查、開關判斷
supabase/migrations/  資料表定義（001～045 與 Next.js 版一致，046 起 Nuxt 版專用）
tests/                測試（utils / shared / server / components；helpers 放假資料庫與 API 測試工具）
docs/                 說明文件
```

## 各模組怎麼運作

### 版面與畫面框架
- `app.vue` 是最外層：大螢幕時置中成 600px 寬的面板（`main.css` 的 `.app-frame`），手機滿版。
- 頁面一律包在 `AuthGate` 裡，沒登入不會顯示頁面內容（見 [登入系統](登入系統.md)）。
- 成員頁使用 `layouts/default.vue`：外框和底部分頁列只寫一次。Next.js 版是每一頁各寫一次外框＋`<TabBar active="...">`。
- 不需要分頁列的頁面（例：隱私權政策）設 `definePageMeta({ layout: false })`。

### 底部分頁列（TabBar）
- 讀網址判斷目前在哪一頁（`/`→請假、`/cancel`→銷假、`/history`→紀錄、`/profile`→個人、`/admin*`→後台），頁面不用傳參數。
- **格數就是權限**：一般成員 4 格；管理員（admin1／admin2）多一格「後台」。權限不足的分頁直接不顯示，不做反灰也不放鎖頭。

### 目前登入者（useMe）
- 用 Nuxt 的 `useState`：同一個 key 在整個 app 內是同一份，任何元件呼叫 `useMe()` 都拿到同一個登入者。
- 提供：`me`（登入者資料）、`isAdmin`、`loading`、`fatal`（無法使用的原因）、`init()`（登入流程，整個 app 只跑一次）、`refresh()`（重讀自己的資料）。

### 呼叫 API（utils/api.ts）
所有前端呼叫後端都用 `api()`，回傳統一格式，呼叫端只看 `ok`：

| 情況 | 回傳 |
|---|---|
| 成功 | `{ ok: true, data }` |
| 後端回錯 | `{ ok: false, status, error }`，`error` 優先用後端的 `error` 訊息，其次伺服器錯誤的 `message`；框架預設的英文（Not Found、Server Error）或都沒有時，用呼叫時給的中文預設文字 |
| 斷線 | `{ ok: false, status: 0, error: '連線失敗，請稍後再試' }` |

Next.js 版每個對話框各寫一遍 fetch／判斷／取錯誤訊息／斷線處理，這裡集中成一個。

### 後端 API 的共同寫法
- 錯誤一律回 `{ error: '訊息' }` 並設狀態碼（`fail(event, 狀態碼, 訊息)`），格式沿用 Next.js 版。
- 讀 body 一律用 `readJson(event)`：讀失敗或 body 是 `null` 都回 `{}`，欄位當成未知型別再逐一檢查，不會因為格式錯誤而 500。
- 需要登入的 API 第一行都是 `currentUser(event)`：從 cookie 驗憑證，**再到資料庫確認角色與是否停用**（不信任憑證裡的舊資料，見 [登入系統](登入系統.md)）。

### 日期（shared/utils/date.ts）
從 Next.js 版原樣搬來（含原專案 30 個測試）。系統在台灣運作但伺服器跑 UTC，所有「時刻→日期」都明確指定 `Asia/Taipei`，不用裝置或伺服器的時區。請假截止、場次是否已開打／已結束等判斷都在這裡。
放在 `shared/`：畫面顯示的截止時間，與後端判斷「能不能請假」用同一份程式（Next.js 版前後端各一份）。規則細節見 [請假頁](請假頁.md#請假截止)。

### 共用規則（shared/utils）
| 檔案 | 用途 | 誰在用 |
|---|---|---|
| `terms.ts` | 現行條款版本 `CURRENT_TERMS_VERSION` | 前端判斷要不要跳同意框、後端寫入同意版本 |
| `setup.ts` | 首次設定卡在哪一關 `setupStage()`、是否完成 `isSetupComplete()` | 首次設定彈窗 |
| `banks.ts` | 常用銀行代號清單、代號／帳號格式檢查 | 退費對話框（前端先擋）、`PATCH /api/me/refund`（後端再驗） |
| `flags.ts` | 環境變數開關判斷 `isFlagOn()` | 測試登入開關（前後端） |
| `date.ts` | 台北日期、請假截止、已開打／已結束 | 場次卡、首頁統計區間、請假 API、統計 API |

### 成員端資料快取（utils/cache.ts）
`cachedApi(url)`：成功結果暫存 20 秒，切分頁不重打；失敗不存。資料一變（請假／銷假成功）或登出，呼叫 `clearMemberCache()` 清掉。詳見 [請假頁](請假頁.md#快取)。

## 開發慣例與注意事項

- **`<template>` 最外層不要在根元素旁放 HTML 註解**：Vue 開發模式會把它當成多個根節點，外部傳入的 `@click`、`style` 會失效（按鈕點了沒反應）。註解寫在 `<script>` 裡或 `<template>` 外。
- **後端要拋錯時，原因寫在 `message`，不要寫在 `statusMessage`**：`statusMessage` 會放進 HTTP 狀態列，只能是英數字，中文會被濾掉（實際踩過：「缺少 Supabase 環境變數」只剩英文）。一般的業務錯誤用 `fail(event, 狀態碼, 訊息)` 即可。
- **環境變數開關一律用 `isFlagOn()` 判斷**：Nuxt 會把 `NUXT_DEV_LOGIN=1` 轉成數字 `1`，用 `=== '1'` 比對永遠不成立（實際踩過）。
- **邊框顏色用 CSS 變數時，寬度／樣式／顏色分開寫**（`borderWidth`、`borderStyle`、`borderColor`），不用 `border` 簡寫，避免不同環境解析不一致。
- **要被測試的元件自己 import 用到的東西**（`vue`、`~/utils/...`、`#shared/...`），不要只靠 Nuxt 自動匯入，否則單獨測試時找不到。
- **共用優先**：同樣的樣式或邏輯出現第二次就抽成元件（`ui/`）或函式（`utils/`、`shared/`）。

## 測試

| 指令 | |
|---|---|
| `pnpm test` | 全部測試（不需要資料庫，也不啟動 Nuxt） |
| `npx vitest run tests/server/leave-api.test.ts` | 只跑一個檔 |

| 要測什麼 | 怎麼寫 |
|---|---|
| 純函式（日期、銀行代號、統計算法） | 直接 import 呼叫 |
| 元件 | `@vue/test-utils` 的 `mount`；元件用到的 `<UiXxx>` 用 `global.components` 註冊，`useMe`、`navigateTo` 等 Nuxt 自動匯入的名稱用 `vi.stubGlobal` 補 |
| 後端 API | `import { harness, asRole, callApi } from '../helpers/nitro'`；`asRole('member', 'me')` 設登入者、`harness.db = fakeDb({ tables, rpc }).db` 設假資料庫，再 `callApi(() => import('#server/api/...'), { body, query })` 拿 `{ status, data }` |

`tests/helpers/nitro.ts` 會把 `server/utils`、`shared/utils` 的真函式補成全域（跟 Nuxt 自動匯入一樣），只有登入者與資料庫是假的，所以權限、格式檢查、截止規則都是真的被測到。**新增 `server/utils` 檔案時，記得加進 `nitro.ts` 的匯入清單**，否則 API 測試會找不到那個函式。

`fakeDb` 會記錄每次查詢的鏈式呼叫（`hasOp(q, ['eq', 'user_id', 'me'])`）與 RPC 參數，用來確認「只查自己的資料」這類條件。

## 與 Next.js 版的對照

| Next.js 版 | Nuxt 版 | 差異 |
|---|---|---|
| `src/app/globals.css` | `app/assets/css/main.css` | 內容相同 |
| `src/app/layout.tsx` | `app/app.vue`＋`layouts/default.vue` | 外框與分頁列寫在 layout |
| `src/liff/LiffProvider.tsx` | `composables/useMe.ts`＋`components/AuthGate.vue` | 流程與畫面判斷拆開 |
| `src/lib/auth/*`、`src/lib/supabase.ts` | `server/utils/*` | 金鑰由參數傳入，不直接讀環境變數 |
| `src/app/api/**/route.ts` | `server/api/**/<名稱>.<方法>.ts` | 一個方法一個檔 |
| `src/lib/types.ts` | `shared/types/index.ts` | 前後端共用 |
| 每個對話框各寫 fetch | `utils/api.ts` | 統一錯誤處理 |
| 每個對話框各寫輸入框樣式 | `<UiInput>`、`<UiErrorText>`、`<UiCheckRow>` | 共用元件 |
