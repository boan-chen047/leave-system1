# 請假頁（首頁）

成員打開 App 的第一頁：上面是本月的出席／已請假場數，下面是「接下來的場次」，每場一張卡片，按「請假」→ 確認 → 完成。

## 畫面與流程

```
打開首頁（首次設定都完成後）
 ├─ 同時抓兩份資料：接下來的場次、本月統計（20 秒內切回來不重抓，見「快取」）
 ├─ 有「請假場次異動」通知 → 跳彈窗（見下方）
 └─ 按某場的「請假」
      → 確認框（顯示是哪一天、幾點、哪裡，避免按錯場）
      → 確定請假
           ├─ 成功：關閉確認框、清快取、重抓 → 那場從清單消失、「已請假」＋1
           └─ 失敗：確認框不關，把原因顯示在框裡（例：已過這場的請假截止時間）
```

載入失敗時畫面保留舊資料，上方出現紅色「資料載入失敗，畫面可能不是最新」＋「重試」，不會把故障誤顯示成「接下來沒有場次」。

## 規則

### 哪些場次會列出
| 場次狀態 | 首頁 |
|---|---|
| 還沒開打、我還沒請假 | ✅ 列出，可按「請假」 |
| 過了請假截止、但還沒開打 | ✅ 照樣列出，按鈕反灰「已截止」（讓成員看得到這週有練球） |
| 我已經請假 | ❌ 不列（改列在銷假頁） |
| 已開打、已取消 | ❌ 不列 |

排序：日期、開始時間由早到晚。

### 請假截止
規則寫在 `shared/utils/date.ts`，**畫面顯示的截止時間和後端判斷能不能請假用的是同一份程式**。

1. **預設：開打前最近的星期二 23:59（台北）**

   | 場次 | 截止 |
   |---|---|
   | 10/09（五）19:30 | 10/06（二）23:59 |
   | 10/04（日）10:00 | 09/29（二）23:59 |
   | 10/06（二）19:30 | 09/29（二）23:59（當天的週二 23:59 已晚於開打，往前抓一週） |

2. **臨時公告的場次：放寬到開打前**。場次的「公告時間」（`sessions.announced_at`：建立的時間；改期改到不同日期或開始時間時會更新）如果已經晚於上面那個週二截止，就改成開打那一刻截止。
   - 例：週三才加開週四的場 → 照預設規則一建立就已截止、永遠請不了假；放寬後開打前都能請。
   - 例：週四把下週五的場改到這週六 → 改完的那一刻已過這週二 → 這週六那場開打前都能請。

3. 開打之後一律不能請。

### 目前 N 人請假
每張卡片顯示這場目前有幾人請假，**只算場次當天「在隊」的人**：

- 「在隊」＝ `membership_periods` 有一段期間涵蓋那天（開始日 ≤ 那天，且結束日為空或晚於那天）。停用當天起就不算。
- 例：小華 9/28 被停用，他之前請過 10/02 的假 → 10/02 那場不算他；他請過 9/25 的假 → 9/25 照算。
- 與後台「依場次查」同一個定義（`server/utils/membership.ts`），兩邊人數一定對得上。

### 本月出席／已請假
查「整個本月」（1 日到月底，台北）：

| 卡片 | 怎麼算 |
|---|---|
| N 月出席 | 本月**已結束**、我在隊、未取消的場次，扣掉我有請假的 |
| N 月已請假 | 已結束場次的請假 ＋ 還沒打但已送出的請假（剛送出的假馬上看得到） |

- 還沒打或打到一半的場次不算出席（還沒有結果）。
- 只算我在隊的期間；中途停用再回來的人，不在隊那段不算。
- 起日最早只到兩年前（兩年前的明細會被清理）。
- 算法在 `server/utils/memberStats.ts`，紀錄頁（第 5 步）與後台依個人查共用，數字一致。

### 請假場次異動通知
管理員把「我已請假的場次」改了日期或時間（單場改期、或改規則連帶影響），資料庫觸發器會替每位請假者記一則通知（migration 044）。

- 首次設定完成後、打開任何需登入的頁面時查一次；有通知就跳「你請假的場次有異動」，列出 ~~原時段~~ → 新時段。
- 請假仍有效。按「知道了」或「去銷假」都會標成已讀、不再跳；已經在銷假頁時不顯示「去銷假」。
- 只提醒還有意義的：請假仍有效、場次未取消、還沒開打。
- 只改地點或備註不通知（不影響能不能來）；改回原時間，未讀通知自動撤掉。

### 快取
成員端的資料（場次、統計）在瀏覽器暫存 20 秒（`app/utils/cache.ts`），切分頁不必每次重打 API。

- 只存成功的結果；失敗不存，下次照樣重抓。
- 請假／銷假成功、或登出換帳號時清掉（不會看到上一個帳號的資料）。

## API

所有 API 需登入（沒登入回 401「未登入」），錯誤一律 `{ error: '訊息' }`。

### `GET /api/sessions/available` — 接下來的場次
回 `SessionRow[]`：

| 欄位 | 說明 |
|---|---|
| `id`、`sessionDate`、`startTime`、`endTime`、`location`、`kind`（`regular` 固定／`extra` 加開）、`description` | 場次資料 |
| `leaveDeadline` | 實際請假截止（ISO 時間） |
| `leaveClosed` | 已過截止（按鈕反灰） |
| `leaveCount` | 目前請假人數（只算當天在隊者） |

| 錯誤 | 情況 |
|---|---|
| 500 | 查詢失敗（含請假人數、我的請假查不到——寧可報錯也不顯示錯的資料） |

### `POST /api/leaves` — 請假
| | |
|---|---|
| body | `{ sessionId: string }`（uuid） |
| 成功 | **201** `{ id }`（請假紀錄 id） |
| 400 | 缺少 sessionId、格式錯誤 |
| 404 | 找不到場次 |
| 409 | 這場已取消／已過這場的請假截止時間／你已經請過這場的假了 |
| 500 | 請假失敗 |

請假與操作紀錄（`leave_actions`，操作者＝自己）由資料庫函式 `self_file_leave` 在同一交易寫入。

### `GET /api/stats/mine?from=YYYY-MM-DD&to=YYYY-MM-DD` — 我的統計
回 `MemberStats`：`sessionsCount`（應出席）、`leaveCount`、`attendCount`、`upcomingLeaveCount`（還沒打的請假）、`leaves`（已結束場次的請假明細）、`appliedFrom`／`appliedTo`（實際套用的區間）、`truncated`（區間被兩年下限或在隊期間調整過）。

| 錯誤 | 情況 |
|---|---|
| 400 | 缺 from／to、不是 YYYY-MM-DD、起日晚於迄日 |
| 500 | 查詢失敗 |

### `GET /api/me/notices` — 未讀的請假場次異動
回 `[{ id, from: { date, start, end }, to: { date, start, end } }]`。

### `POST /api/me/notices` — 標成已讀
| | |
|---|---|
| body | `{ ids: string[] }`（1～50 個 uuid） |
| 成功 | `{ ok: true }`。只會更新自己的、還沒讀的 |
| 400 | ids 不是陣列、空的、超過 50 個、混入非 uuid（整批擋） |

## 與 Next.js 版差異

| 項目 | Next.js 版 | Nuxt 版 |
|---|---|---|
| 截止規則 | 前端、後端各有一份 `date.ts` | `shared/utils/date.ts` 一份，前後端共用 |
| 異動通知彈窗 | 只掛在首頁、銷假頁 | 掛在所有需登入的頁面 |
| 「我的請假」查詢失敗 | 當成沒請過，已請假的場次會又出現在清單 | 回 500，畫面顯示重試 |
| 同一天兩場 | 只按日期排 | 日期、開始時間都排 |
| 統計 API 日期參數 | 不檢查，格式錯變 500 | 先檢查，回 400 |
| 請假 sessionId | 不檢查格式 | 非 uuid 回 400 |
| 確認框 | 另寫一個 ConfirmSessionDialog | 共用 ConfirmDialog ＋ SessionSummary |
| 換帳號 | — | 登出時清快取 |
